## Dataset Strategy & Training Setup

### Single-Model, Multi-Role Approach

When using a **single model for three roles**, you need **three datasets** to train the adapters.

Lua datasets:
https://huggingface.co/datasets?search=lua

Synthetic data should be generated using a **more powerful LLM**.  
Initially, **200–500 high-quality examples per adapter** are sufficient.

## 2. Critic Dataset (Incorrect Lua Code)

Dataset file: `critic_data.jsonl`  

Contains pairs:
**"code with a typical error — constructive feedback"**

Example:
```json
{
  "instruction": "Analyze this Lua code for errors:\n\nfunction test()\n  local x = 10\n  y = 20\n  return x + y\nend",
  "output": "A potential issue is detected: variable 'y' is missing the 'local' keyword. This creates a global variable, which may lead to hard-to-debug errors. It is recommended to declare it as 'local y = 20'."
}
```

## 3. Dialogue Dataset (Analyst Role)

### Step 1 — Generate Dialogues

Create a dialogue generation template.

Use a stronger model (e.g., GigaChat) to generate diverse dialogues where:

- the initial task is vague  
- the analyst asks the right clarifying questions  
- all details are clarified  

### Example Prompt

> Generate a dialogue between a programmer who wants to write a Lua script and an AI assistant.  
> Start with a vague request like "I need a script to process data".  
> The assistant should ask 3–5 specific clarifying questions (data source, format, required processing, output destination).  
> The programmer provides clear answers.  
> At the end, the assistant states readiness to write the code and lists the key points it has understood.

---

### Step 2 — Convert Dialogues to Training Format

Convert dialogues into **instruction–response format** for LoRA:

- **Instruction:** initial user request  
- **Output:** list of clarifying questions generated by the analyst

## QLoRA + Unsloth

### QLoRA

- Compresses the base model (e.g., MultiPLCoder-1B) into **4-bit precision during training**
- Reduces VRAM usage:
  - from ~4–5 GB → ~1.1 GB  
- Enables training on:
  - free GPU (Tesla T4, 15 GB VRAM in Google Colab)

---

### Unsloth

- Speeds up training **2–5×**
- Reduces memory usage by up to **80%**
- Optimizes internal training processes

## Training Plan: Three Specialists

The training process is the same for all adapters — only the datasets differ.

---

### Analyst Adapter

**File:** `analyst_data.jsonl`  
**Goal:** learn to ask clarifying questions  

Dataset:
- vague tasks  
- model outputs 3–5 clarifying questions  

---

### Generator Adapter

**File:** `generator_data.jsonl`  
**Goal:** generate Lua code  

Format:
```json
{
  "instruction": "Task in Russian/English",
  "output": "Ready-to-use Lua code"
}
```

---

### Critic Adapter

**File:** `critic_data.jsonl`  
**Goal:** validate code  

Format:
```json
{
  "instruction": "Review the code",
  "output": "Error report (optionally in JSON format)"
}
```

---

## Example Dataset Entry

{
  "instruction": "Write a Lua function that calculates factorial.",
